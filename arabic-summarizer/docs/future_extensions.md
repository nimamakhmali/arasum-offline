# نقاط توسعه آینده معماری

این موارد برای MVP فعلی ضروری نیستند، اما برای توسعه‌های بعدی پیشنهاد می‌شوند:

1. **BaseCache Interface**: اگر بعداً نیاز به backend دیگری غیر از SQLite
   (مثل Redis برای مقیاس بزرگ‌تر) بود، یک کلاس انتزاعی `BaseCache` تعریف
   و `CacheManager` را از آن مشتق کنید.

2. **پشتیبانی از GGUF/llama.cpp**: فقط در صورتی که مدل پایه از خانواده
   Llama انتخاب شود (نه AraBART/AraT5).

3. **Batch Commit در Cache**: در صورت افزایش شدید ترافیک، از تراکنش‌های
   دسته‌ای در SQLite یا WAL mode استفاده کنید.
