## ۳. الزامات غیرعملکردی

- **آفلاین کامل**: هیچ درخواستی به اینترنت ارسال نمی‌شود
- **سازگاری سخت‌افزار**: Intel Core i7-12700H، RAM 16GB، بدون GPU اجباری
- **قابلیت نصب**: Docker و pip install هر دو پشتیبانی می‌شوند
- **Thread Safety**: API server باید چند درخواست همزمان را مدیریت کند
- **امنیت داده**: تمام پردازش روی سرور محلی، هیچ داده‌ای ارسال نمی‌شود

## ۴. تصمیمات معماری

### چرا AraBART؟
مدل `moussaKam/AraBART` تنها مدل Encoder-Decoder است که 
نه‌تنها pretrain شده بلکه به‌طور خاص برای summarization 
عربی fine-tune شده است. AraT5 به عنوان جایگزین پشتیبان 
در نظر گرفته شده.

### چرا ONNX Runtime؟
- سرعت inference بالاتر از PyTorch خالص در CPU
- حجم کمتر وابستگی‌ها نسبت به TensorFlow
- پشتیبانی از INT8 Quantization بدون افت کیفیت محسوس
- cross-platform (Windows/Linux)

### چرا FastAPI؟
- async native که برای I/O-bound tasks مناسب است
- تولید خودکار مستندات Swagger
- Pydantic integration برای validation قوی
- سبک‌تر از Django برای یک microservice

## ۵. محدودیت‌های Scope

موارد زیر **خارج از scope** این پروژه (فاز اول) هستند:
- پردازش PDF و OCR (فاز دوم)
- پشتیبانی از عربی محاوره‌ای و گویش‌ها
- خلاصه‌سازی چند سندی
- پردازش دسته‌ای (Batch)
- Authentication و Authorization در API
